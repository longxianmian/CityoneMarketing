# CityOne 营销增长系统接入阿里云 OSS 开发执行文档（开发环境版）

## 一、任务背景

当前 CityOne 营销增长系统需要正式接入阿里云 OSS，用于存储：

* 活动图片
* 商品图片
* 卡券封面图
* 海报生成图
* 用户上传图片
* 短视频/宣传视频

已确认的 OSS Bucket 信息如下：

* Bucket：`cityone-marketing`
* 地域：`新加坡`
* Endpoint：`oss-ap-southeast-1.aliyuncs.com`
* 访问策略：**私有 Bucket**
* 阻止公共访问：**开启**

本次开发目标不是做公开图床，而是为营销增长系统建立一套**可持续扩展的媒体资产存储能力**。

---

## 二、本次开发目标

请在当前营销增长系统的开发环境中，完成一套 **“后端上传 OSS + 后端签名访问 + 前端预览/保存 key”** 的最小可用实现。

### 本次必须达成

1. 管理端可上传图片、视频到 OSS
2. 后端将文件上传到 OSS
3. 后端保存媒体元数据
4. 前端拿到可预览地址进行显示
5. 活动/商品/卡券等业务记录中保存 `object_key` 或 `media_asset_id`
6. 前端不得直接持有阿里云长期密钥
7. Bucket 保持私有，不改成公共读

---

### 2）不要改业务方向

本次只是新增 OSS 媒体能力，不允许擅自改动现有营销增长系统的业务逻辑、表单流程、页面结构。

### 3）开发环境优先稳

阿里云密钥只允许存在后端环境变量中。

## 五、推荐实现方案

本次采用 **Phase 1：后端中转上传 OSS** 方案。

即：

* 前端上传文件到后端接口
* 后端收到文件后上传到 OSS
* 后端返回 `object_key + preview_url + media_asset_id`
* 前端保存返回结果到当前业务表单

这是当前开发环境最稳、最容易验证的做法。

## 六、后端改造要求

## 6.1 新增依赖

请根据当前后端技术栈安装需要的依赖。

如果是 Node.js + Express，优先考虑：

```bash
npm install ali-oss multer uuid mime-types
```

如项目已有上传中间件或文件处理库，则优先复用，不要重复引入。

---

## 6.2 新增环境变量

请在后端环境变量中新增以下配置：

```env
ALIYUN_OSS_REGION=oss-ap-southeast-1
ALIYUN_OSS_BUCKET=cityone-marketing
ALIYUN_OSS_ENDPOINT=oss-ap-southeast-1.aliyuncs.com
ALIYUN_OSS_ACCESS_KEY_ID=你的AK
ALIYUN_OSS_ACCESS_KEY_SECRET=你的SK
ALIYUN_OSS_URL_EXPIRES=3600
MEDIA_MAX_IMAGE_SIZE=10485760
MEDIA_MAX_VIDEO_SIZE=209715200
```

说明：

* 图片默认最大 10MB
* 视频默认最大 200MB
* `ALIYUN_OSS_URL_EXPIRES` 为签名 URL 过期时间，先用 3600 秒

---

## 6.3 新增 OSS 服务层

请新增一个独立的 OSS 服务模块，例如：

```text
src/services/ossService.js
```

职责包括：

1. 初始化 OSS 客户端
2. 上传文件到 OSS
3. 生成签名访问 URL
4. 删除 OSS 文件（可预留）
5. 根据业务模块生成规范化 objectKey

---

## 6.4 objectKey 规范

请统一使用以下路径规则：

```text
activities/{activityId}/cover/{timestamp}-{random}.{ext}
activities/{activityId}/gallery/{timestamp}-{random}.{ext}
products/{productId}/cover/{timestamp}-{random}.{ext}
coupons/{couponId}/cover/{timestamp}-{random}.{ext}
posters/{campaignId}/generated/{timestamp}-{random}.{ext}
videos/{module}/{yyyy}/{mm}/{timestamp}-{random}.{ext}
uploads/temp/{yyyy}/{mm}/{dd}/{timestamp}-{random}.{ext}
```

### 要求

* 不要直接使用原始文件名落 OSS
* 文件名统一用：`时间戳 + 随机串 + 后缀`
* 后缀根据真实 MIME 或扩展名保留

---

## 6.5 新增媒体表

如果当前项目支持数据库迁移，请新增统一媒体表：

### 表名建议

```text
media_assets
```

### 字段建议

```text
id
bucket
object_key
original_name
mime_type
size_bytes
width
height
duration_seconds
module_type
module_id
uploaded_by
status
created_at
updated_at
```

### 说明

* `module_type`：如 `activity/product/coupon/poster/video/temp`
* `module_id`：业务主键，可为空
* `status`：如 `active/deleted/temp`

如果当前项目短期内不方便建新表，也至少要保证：

* 业务表能保存 `object_key`
* 后续可以平滑升级为统一媒体表

但优先推荐建表，不要每个模块各写一套上传逻辑。

---

## 6.6 新增接口

请新增以下接口：

### 1）上传接口

```http
POST /api/media/upload
```

#### 请求方式

`multipart/form-data`

#### 参数

* `file`：文件本体，必填
* `moduleType`：业务模块类型，如 `activity/product/coupon/poster/video/temp`
* `moduleId`：业务 ID，可选
* `usage`：如 `cover/gallery/video/avatar`，可选

#### 返回示例

```json
{
  "success": true,
  "data": {
    "id": "media_xxx",
    "bucket": "cityone-marketing",
    "objectKey": "activities/123/cover/1710000000-abcd1234.jpg",
    "originalName": "banner.jpg",
    "mimeType": "image/jpeg",
    "sizeBytes": 234567,
    "previewUrl": "https://签名地址",
    "expiresIn": 3600
  }
}
```

---

### 2）获取预览地址接口

```http
GET /api/media/view-url?key=xxx
```

#### 返回示例

```json
{
  "success": true,
  "data": {
    "objectKey": "activities/123/cover/1710000000-abcd1234.jpg",
    "previewUrl": "https://签名地址",
    "expiresIn": 3600
  }
}
```

---

### 3）删除接口（可先预留）

```http
DELETE /api/media/:id
```

先实现软删除或仅预留结构即可，不要求本次必须打通到业务页面。

---

## 6.7 上传校验

后端必须增加以下校验：

### 图片允许类型

```text
image/jpeg
image/png
image/webp
image/gif
```

### 视频允许类型

```text
video/mp4
video/webm
video/quicktime
```

### 大小限制

* 图片：10MB
* 视频：200MB

### 必须做的保护

* 缺少文件时报错
* MIME 不合法时报错
* 超大小时报错
* OSS 上传失败时报错
* 不要返回裸露的 AK/SK 或错误栈给前端

---

## 6.8 后端实现要点

### 上传逻辑

1. 接收前端文件
2. 校验类型与大小
3. 根据 `moduleType/moduleId/usage` 生成 objectKey
4. 上传到 OSS
5. 保存媒体元数据到数据库
6. 生成签名预览 URL
7. 返回媒体信息给前端

### 访问逻辑

1. 前端传入 `objectKey`
2. 后端生成带过期时间的签名 URL
3. 返回给前端使用

## 7.1 管理端上传入口

请在以下页面接入通用上传能力：

* 活动管理
* 商品管理
* 卡券管理
* 海报管理（如已有）
* 视频素材管理（如已有）

---

## 7.2 上传方式

前端统一调用：

```http
POST /api/media/upload
```

不要前端直接调用 OSS，不要在前端写阿里云上传 SDK，不要在前端保存 AK/SK。

---

## 7.3 上传成功后的表单处理

上传成功后，请将以下信息写回表单状态：

```json
{
  "mediaAssetId": "xxx",
  "objectKey": "activities/123/cover/xxx.jpg",
  "previewUrl": "https://签名地址"
}
```

### 表单保存时

* 业务表中保存 `media_asset_id` 或 `object_key`
* 不要保存 base64 图片
* 不要把整个文件内容塞进数据库

---

## 7.4 页面预览

### 图片预览

* 直接使用 `previewUrl`

### 视频预览

* 使用 `video` 标签展示 `previewUrl`

### 注意

签名 URL 会过期，所以：

* 列表页如果已有永久预览机制则复用
* 如签名过期，可重新请求 `/api/media/view-url`

---

## 7.5 前端校验

上传前先做基础校验：

* 图片类型校验
* 视频类型校验
* 大小校验
* 上传中状态
* 上传失败提示
* 预览加载失败兜底

## 八、建议的前端抽象

请尽量抽成一个通用上传组件，例如：

```text
components/MediaUploader
```

支持参数：

* `moduleType`
* `moduleId`
* `usage`
* `accept`
* `maxSize`
* `multiple`
* `mediaType`

支持返回：

* `mediaAssetId`
* `objectKey`
* `previewUrl`

这样活动、商品、卡券都可以复用，不要每个页面各写一套上传逻辑。

## 九、CORS 与 Bucket 策略

本次 Phase 1 因为是“前端传后端，后端传 OSS”，前端本身不直接跨域请求 OSS，所以不要求前端立刻对接 OSS CORS。

但请在代码里预留后续扩展能力，方便第二阶段升级为：

* 后端签发上传签名
* 前端直传 OSS
* Bucket 配置 CORS
* 上传成功回调落库
