## 二、本轮整改目标（明确版）

本轮不是再写空泛方案，而是落实以下 4 个明确目标。

### 目标 1：收口 `site_id` → `station_code`

* `station_code` 成为增长系统里正式站点标识
* `site_id` 保留为 legacy 兼容字段，不再作为新逻辑主字段
* 入口模块逐步完成从 `site_id` 到 `station_code` 的过渡

### 目标 2：压实 A 系统映射字段的唯一性与可用性

* `a_system_station_id`
* `a_system_device_id`
* `device_code`
  这些字段必须成为后续旁路连接的可靠映射位

### 目标 3：把站点归因快照正式纳入结果表写入链路

* `activity_participations`
* `points_ledger`
  要稳定写入站点快照

### 目标 4：为 A 系统 webhook / 同步接口预留代码落点

虽然这轮不真实对接 A 系统，但要把增长系统侧接入点准备好，避免后面又推倒重来。

## 三、按文件路径的具体修改要求

# 模块 A：site_id → station_code 过渡收口

## 1. 文件：`backend/src/routes/entries.js`

### 这轮必须改什么

1. 明确创建/更新入口时：

   * `station_code` 为新正式字段
   * `site_id` 为 legacy 兼容字段
2. 创建/更新时如果传入 `station_code`：

   * 必须查询 `stations` 表确认该 `station_code` 存在
   * 不存在时返回明确错误（建议 422）
3. API 响应中：

   * 当前阶段仍可返回 `site_id`
   * 但必须同时返回 `station_code`
4. 所有新写入逻辑优先写 `station_code`
5. 如果同时收到 `site_id + station_code`：

   * 以 `station_code` 为准
   * `site_id` 仅做兼容保留

### 当前阶段不要做什么

* 不要在这一轮删除 `site_id`
* 不要强行修改 `entry-routing-config.js`
* 不要把 `routes/routes.js` 里的 `site_id` 一起替换

### 完成后的验证

* `POST/PUT /api/entries/...` 传 `station_code` 可成功保存
* 传不存在的 `station_code` 返回明确错误
* 旧前端仍可展示 `site_id/site_name`
* 新接口响应中已有 `station_code`

---

## 2. 文件：`backend/scripts/backfill-entry-station-code.js`

### 这轮必须改什么

1. 保留 `--dry-run` 模式
2. 在脚本顶部明确维护映射表，例如：

   * `site_001 -> st_xxx`
   * `site_002 -> st_xxx`
3. 执行逻辑必须输出：

   * 总入口数
   * 已有 `station_code` 数
   * 待回填数
   * 成功回填数
   * 无法映射数
4. 干跑时不能改 DB
5. 正式执行时只更新 `station_code` 为空的记录

### 这轮建议补充

将日志输出更明确，例如：

* `entry_002: site_001 -> st_00x`
* `entry_003: site_002 -> 未配置映射，跳过`

### 完成后的验证

* `node backend/scripts/backfill-entry-station-code.js --dry-run` 输出清晰
* 填入映射后执行，DB 中 `entry_instances.station_code` 被正确回填

---

## 3. 文件：`src/features/growth/EntryCenter.tsx`

### 这轮必须改什么

1. 在现有 `site_id/site_name` 表单区块旁，新增：

   * `station_code` 选择器
2. 选择器数据来源：

   * 从 `GET /api/stations` 拉取
3. 展示格式建议：

   * `station_code + 站点名称`
4. 提交时：

   * 保留旧 `site_id` 字段
   * 同时提交 `station_code`
5. 页面上增加提示：

   * `site_id` 为旧字段
   * `station_code` 为正式站点绑定字段

### 当前阶段不要做什么

* 不要删旧 `site_id` 输入项
* 不要让旧入口编辑页白屏

### 完成后的验证

* 入口管理页能拉到站点列表
* 选中站点后可提交成功
* 编辑已有入口不会因缺少 `station_code` 崩溃

# 模块 B：A 系统映射字段防重压实

## 4. 文件：`backend/src/routes/stations.js`

### 这轮必须确保已实现 / 如未完整实现则补齐

1. 在创建站点与更新站点逻辑中，统一调用：

   * `validateASystemFieldUniqueness()`
2. 校验字段至少包括：

   * `a_system_station_id`
   * `a_system_device_id`
   * `device_code`
3. 校验规则：

   * 空字符串不参与查重
   * 非空值必须唯一
   * 更新自身时排除自身
4. 错误返回必须清晰中文化，例如：

   * `A_SYSTEM_FIELD_DUPLICATE: A系统站点ID xxx 已被站点 st_001 使用`
   * `A_SYSTEM_FIELD_DUPLICATE: 设备编码 xxx 已被站点 st_002 使用`
5. 在 `rowToStation()` 或等价映射函数中，确保以下字段始终能回给前端：

   * `station_code`
   * `a_system_station_id`
   * `device_code`
   * `device_group_code`
   * `a_system_device_id`

### 当前阶段不要做什么

* 不要把 A 系统字段迁到别的表
* 不要因为想“更规范”而强拆 `station_devices` 表

### 完成后的验证

* 创建重复 `a_system_station_id` 报 409
* 创建重复 `device_code` 报 409
* 更新自身记录不误报冲突
