# CityOne 三语与未完成功能整改执行文档（唯一母本）

## 一、文档定位

本文件是当前 **CityOne 营销增长系统“三语整改 + 未完成功能补齐”** 的唯一执行母本。

本次整改不是普通 bug 修复，而是一次 **口径纠偏 + 架构纠偏 + 页面补齐**。

本次整改的直接原因有两类：

### 1）三语方案被错误实现

当前系统出现了以下严重偏差：

* 将“三语能力”错误实现成“管理员在模板里分别输入中文 / 泰文 / 英文”
* 后台页面大量直接显示 i18n key，如：

  * `admin.agentConfig.pageTitle`
  * `admin.riskRule.btnAdd`
  * `admin.message.btnSearch`
* 多个页面虽然有语言切换按钮，但页面内容并没有真正跟随语言切换
* 管理端模板页出现“三语输入 tab”，与既定方案冲突

### 2）大量页面和模块仍未完善

当前仍存在：

* 大量后台页面没有完成真正的多语言支持
* 大量页面仍是半成品、占位页或仅完成结构
* 大量功能模块只有表壳，没有真实字段、真实说明或真实交互
* 多个系统配置页、Agent 页、记录页、规则页尚未达到可运营状态

本次整改的唯一目标是：

**把错误的三语实现彻底纠正，把相关模板、页面、功能模块按既定方案整改到可继续稳定开发的正确基线。**

---

## 二、必须先纠正的核心认知

以下认知必须作为本次整改的最高约束，任何代码实现不得违背。

### 1. 三语不是“后台人工录三语”

错误理解：

* 模板表单里让管理员分别填写中文 / 泰文 / 英文
* 后台大量出现三个输入框或三个 tab 让人手工录入三种语言

正确理解：

**后台运营只输入一种语言内容。保存时由 AI 自动补翻成另外两种语言，统一存储，再由前端按当前系统语言自动切换显示。**

---

### 2. 三语的目标是“所有内容可跟随系统切换语言”

正确目标不是“表单里能看见三语 tab”。

正确目标是：

* 用户把系统切到中文，全站内容显示中文
* 切到泰文，全站内容显示泰文
* 切到英文，全站内容显示英文
* 静态 UI 文案与动态运营内容都能正确跟随切换

---

### 3. 静态 UI 与动态内容必须分治

#### 静态 UI

适用：

* 菜单
* 按钮
* 表格列名
* 筛选项
* 标题
* 提示文案
* 空状态
* 弹窗固定说明

正确方式：

* 统一走 `t('...')`
* 所有 key 必须在 `src/i18n/index.tsx` 中完整提供

#### 动态内容

适用：

* 活动标题
* 活动副标题
* 卡券名称
* 权益名称
* 承接页运营文案
* 欢迎语模板
* Prompt 模板内容

正确方式：

* 后端存 `{ zh, th, en }` 对象
* 前端读取走 `pickLocalizedText(...)`
* 保存时自动翻译补全缺失语言

---

### 4. 管理端不是“不做多语”

当前旧文档里有一句“后台不做多语”，这不能继续当执行依据。

从当前项目实际要求出发：

**管理端也必须支持中 / 泰 / 英切换，至少所有页面静态 UI 必须能正确切换。**

但管理端的“动态运营内容录入”仍然遵循：

* 单语输入
* 保存时自动补翻
* 不要求后台人员手工分别录三语

---

## 三、当前既定三语方案（本次整改唯一依据）

以下口径必须严格执行。

### 1）语言识别与切换机制

优先级固定为：

* 手动设置
* 浏览器语言
* 默认英语

存储 key 固定为：

* `cityone_growth_lang`
* `cityone_growth_lang_mode`

语言映射固定为：

* `zh* -> zh`
* `th* -> th`
* `en* -> en`

该方案在你提供的文档中已有明确说明。fileciteturn1file0

---

### 2）静态 UI 文本方案

所有写死在页面里的固定标签、按钮、提示文案，必须统一走 `t('...')`。文档中已明确给出 `useI18n()` 与 `t(...)` 的使用方式，并说明其适用范围就是所有固定 UI 文本。fileciteturn1file0

这意味着：

* 页面中不得直接写死中文
* 页面中不得直接露出 i18n key
* 页面中不得局部实现、多处漏翻

---

### 3）动态内容方案

动态内容必须按 `{ zh, th, en }` 三语对象存储，前端读取走 `pickLocalizedText(...)`，并遵循降级规则：

`当前语言 -> en -> zh -> th -> 空字符串`。该结构、读取方式与降级规则在文档中都已经明确。fileciteturn1file1turn1file3

---

### 4）AI 自动翻译方案

管理员在后台保存活动、产品、落地页模板时，系统自动调用翻译接口补齐另外两种语言；已明确包含：

* `ActivityTemplateManage`
* `ProductTemplateManage`
* `LandingTemplateManage`
* `MultiLangInput` 组件

并由 `POST /api/translate` 处理翻译。fileciteturn1file3

这意味着：

**后台不是让人手工把三种语言都填完，而是只输入一种语言，然后自动补齐。**

## 五、本次整改的固定目标

### 目标1：彻底取消“模板里人工录三语”的错误实现

所有模板类页面必须整改为：

* 管理员只输入一种源语言内容
* 系统自动识别当前录入语言或按规则传入 `sourceLang`
* 保存时调用翻译接口补齐其余两种语言
* 前端表单默认展示“单语录入视图”
* 如需查看其他语言版本，只允许做“展开查看”或“翻译结果预览”，不得要求人工逐项填写三语

---

### 目标2：后台静态 UI 全面接入 i18n

所有后台页面静态 UI，必须整改为：

* 页面标题
* 卡片标题
* 表格列名
* 筛选项
* 按钮
* 空状态
* 表单标签
* 开关说明
* tab 标题

全部走 `t('...')`，不允许再出现 key 裸露。

---

### 目标3：动态内容读取与展示彻底统一

所有动态运营内容页面必须统一为：

* 读取：`pickLocalizedText(...)`
* 存储：`{ zh, th, en }`
* 保存：单语输入 + 自动补翻

不允许：

* 某页面自己拼字段
* 某页面直接拿 `titleZh` / `titleTh` / `titleEn` 各写一套
* 某页面把三语 tab 当作必填录入方案

---

### 目标4：系统配置、Agent、记录、规则等页面静态文案全部可切换中泰英

重点页面包括但不限于：

* Agent 配置
* 意图管理
* 工具管理
* 会话日志
* 指标看板
* LINE OA 配置
* 三语配置
* 风控规则
* 消息触达
* 基础系统参数

这些页面当前大量直接显示 key，必须本轮全部整改。

---

### 目标5：未完成功能模块进行一次系统性收敛

本轮不要求所有模块都 fully done 到生产级闭环，但必须做到：

* 页面能用
* 页面文案完整
* 页面结构完整
* 关键字段和交互完整
* 不再是大量半成品堆积
