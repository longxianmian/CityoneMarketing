# 文档二：营销增长系统 OSS 接入整改文档

## 一、整改目标
将营销增长系统中的图片、视频、活动素材、商品素材、上传资源统一接入阿里云 OSS，不再继续使用本地临时目录、临时静态路径或混乱文件承接方式。

## 二、整改原则
1. 上传文件必须统一进入 OSS
2. 上传成功后必须回写数据库元数据
3. 文件归属必须可追踪
4. URL / Key / Bucket / 业务对象关系必须明确
5. 不允许继续让文件只存在本地临时目录却没有数据库记录

## 三、必须先做的检查
你不要先写上传代码，必须先看真实项目当前怎么处理文件。

### 先确认以下内容
1. 当前项目里有哪些上传入口
2. 当前文件保存到哪里：
   - 本地目录
   - 静态资源目录
   - 临时路径
   - 旧 OSS 逻辑
   - 未真正落盘
3. 前端上传接口有哪些
4. 后端接收上传的路由、控制器、服务在哪
5. 当前数据库是否已有文件字段、素材字段、封面字段

## 四、需要优先查看的真实文件
### 后端
- 上传接口文件
- 中间件文件（multer / upload / file 相关）
- 静态资源路径配置
- 资源 URL 拼接逻辑

### 前端（管理端 / 用户端）
- 活动上传入口
- 商品上传入口
- 卡券封面上传入口
- 富文本或图文编辑中的上传入口
- 预览与回显组件

## 五、整改要求
### 第一阶段：梳理上传点
先列出系统当前所有上传点，至少覆盖：
- 活动封面
- 活动详情图
- 商品封面
- 商品详情素材
- 卡券封面
- 运营素材
- 其它前端实际存在的上传点

### 第二阶段：统一 OSS 上传策略
基于真实代码做统一整改：
1. 新增或修正 OSS 配置读取
2. 将文件上传逻辑统一改为上传 OSS
3. 返回标准化文件信息对象
4. 将 OSS 返回结果回写数据库

建议至少记录以下字段：
- bucket
- object_key
- file_url
- file_name
- mime_type
- file_size
- business_type
- business_id
- uploader_id
- created_at

### 第三阶段：路径规则统一
你需要给出统一的 OSS Key 命名规则，建议按业务对象分目录，例如：
- `growth/activities/...`
- `growth/products/...`
- `growth/coupons/...`
- `growth/assets/...`

注意：目录规则必须结合真实项目字段与实际用途来定，不要空想。

### 第四阶段：数据库元数据落库
如果当前没有独立素材表，则请评估：
- 是先在业务表中补充文件字段
- 还是建立统一素材表 `media_assets`

需要基于真实项目复杂度做判断，并说明原因。

## 六、技术执行要求
### 1. 配置要求
OSS 配置必须走环境变量，不允许写死。

### 2. 返回值要求
上传接口返回结构要统一，便于管理端 / 用户端复用。

### 3. 前端要求
管理端上传成功后：
- 可预览
- 可回显
- 可提交保存
- 保存后后端真实记录文件信息

### 4. 不允许做的事
- 不允许只把文件传上 OSS 但不回写数据库
- 不允许继续依赖本地目录作为正式方案
- 不允许前端只显示假 URL
- 不允许随意新造一整套上传中心而脱离现有代码

## 七、验收标准
整改完成后，必须满足：
1. 至少一个活动上传点打通
2. 至少一个商品上传点打通
