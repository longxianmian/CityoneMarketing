# CityOne 多语言方案（完整稿）

## 一、方案总原则

CityOne 的多语言不是“人工分别录入中文、泰文、英文三套内容”，而是分成两套机制统一处理：

### 1. 静态 UI 多语言
适用于：
- 页面标题
- 菜单
- 按钮
- 固定提示语
- 导航栏
- 页脚
- 固定说明文字

处理方式：
- 统一写入前端 i18n 语言包
- 前端通过 `t('xxx.xxx')` 读取
- 管理端与用户端共用同一套中 / 泰 / 英语言机制

### 2. 动态内容多语言
适用于：
- 活动标题
- 活动描述
- 卡券名称
- 商品名称
- 模板内容
- 运营配置内容
- API 返回的展示字段

处理方式：
- 后台只需录入一种语言
- 保存时自动调用 AI 翻译补齐另外两种语言
- 后端统一保存为 `{ zh, th, en }` 结构
- 前端按当前语言自动读取展示

---

## 二、最终统一规则

CityOne 多语言的最终规则只有一句话：

**管理端和用户端都必须支持中 / 泰 / 英三语切换；静态内容走 i18n；动态内容走 `{ zh, th, en }`；后台录入只需输入一种语言，其余两种由 AI 自动补齐。**

这意味着：
- 不是后台只做中文、前台才做三语
- 不是要求运营手工填三份语言内容
- 不是只翻译活动内容、不翻译系统页面
- 而是整个系统都必须是统一三语方案

---

## 三、语言识别与切换机制

### 1. 优先级

```text
手动设置 > 浏览器 / 系统语言 > 默认英语
```

### 2. 本地存储 Key

```text
cityone_growth_lang       当前语言（zh / th / en）
cityone_growth_lang_mode  语言模式（auto / manual）
```

### 3. 语言映射规则

```text
zh* → zh
th* → th
en* → en
其他 → en
```

### 4. 执行结果

- 默认跟随用户电脑 / 手机浏览器语言
- 用户可手动切换为中文 / 泰文 / 英文
- 一旦手动切换，优先使用手动设置
- 未匹配语言时默认英文兜底

---

## 四、静态 UI 多语言方案

### 1. 适用范围

所有写死在前端代码里的固定文字，例如：
- 福利中心
- 首页
- 我的
- 活动中心
- 积分兑换
- 立即参与
- 分享
- 附近站点
- 系统说明
- 隐私政策
- 用户协议
- 底部导航
- 管理端菜单

### 2. 技术方式

```tsx
const { t, language } = useI18n()

t('welfare.title')
t('common.agent')
t('mine.languageSub')
```

### 3. 实施要求

- 所有固定文案必须进入 i18n 词典
- 禁止在页面组件中直接写死中文 / 泰文 / 英文
- 新页面上线前必须补齐 `zh / th / en` 三语 key
- 管理端与用户端共用语言底座，但各自维护各自模块 key

---

## 五、动态内容多语言方案

### 1. 适用范围

所有由后台配置、运营录入、接口返回的展示内容，例如：
- 活动标题
- 副标题
- 描述
- 奖励说明
- 注意事项
- 卡券名称
- 商品名称
- 按钮文案
- 落地页内容

### 2. 统一存储结构

```json
{
  "title": {
    "zh": "扫码领券活动",
    "th": "กิจกรรมสแกนรับคูปอง",
    "en": "Scan & Get Coupons"
  },
  "description": {
    "zh": "限时活动，先到先得",
    "th": "กิจกรรมจำกัดเวลา",
    "en": "Limited time offer"
  }
}
```

### 3. 统一读取方式

```tsx
const title = pickLocalizedText({ title: activity.title }, 'title', language)
```

### 4. 统一降级规则

```text
当前语言 → en → zh → th → 空字符串
```

### 5. 作用

这样可以避免：
- 某个语种为空时页面直接空白
- 页面因为某种语言缺失而报错
- 各个页面自己乱写兼容逻辑

---

## 六、后台录入与自动翻译机制

### 1. 正确流程

1. 管理员录入一种主语言内容
2. 点击保存
3. 系统识别源语言
4. 自动调用翻译接口
5. 补齐另外两种语言
6. 保存为 `{ zh, th, en }` 结构
7. 前端按当前语言自动展示

### 2. 推荐要求

后台不应只支持“中文录入后翻译”。
而应支持：
- 中文录入
- 泰文录入
- 英文录入

系统自动识别 `sourceLang`，再补齐剩余两种语言。

这样更符合泰国本地运营和后续扩展需求。

---

## 七、翻译接口规范

### 请求示例

```json
{
  "texts": {
    "title": "扫码领券活动",
    "description": "限时福利，先到先得"
  },
  "sourceLang": "zh"
}
```

### 响应示例

```json
{
  "result": {
    "title": {
      "zh": "扫码领券活动",
      "th": "กิจกรรมสแกนรับคูปอง",
      "en": "Scan & Get Coupons"
    },
    "description": {
      "zh": "限时福利，先到先得",
      "th": "สิทธิ์จำกัดเวลา มาก่อนได้ก่อน",
      "en": "Limited-time perks — first come, first served"
    }
  }
}
```

## 八、前后端统一执行标准

### 前端

#### 静态文案
统一使用：

```tsx
t('module.key')
```

#### 动态文案
统一使用：

```tsx
pickLocalizedText(data, field, language)
```

### 后端

统一保存结构：

```json
{ "zh": "...", "th": "...", "en": "..." }
```

### 后台录入组件

统一使用支持三语对象的录入组件，例如：
- 单语输入 + 自动翻译补齐
- 三语输入框 + 一键翻译补全

这是调用 OpenAI / ChatGPT 做自动翻译时必须使用的翻译角色设定，不能省略。

```text

【中泰英三语翻译专家】

- 英语翻译面向东南亚英语受众，简洁友好，避免过于正式的欧美腔

模型：gpt-5-mini
输出格式：JSON（json_object 模式，不输出 markdown 代码块）
```

## 十、开发验收标准

### 验收 1
用户端切换语言后，所有固定 UI 文案同步切换。

### 验收 2
管理端切换语言后，所有固定 UI 文案同步切换。

### 验收 3
后台新建活动 / 商品 / 模板时，只输入一种语言，保存后自动补齐另外两种。

### 验收 4
活动页、卡券页、商品页、详情页能按当前语言正确展示动态内容。

### 验收 5
任一语种缺失时，系统按 `当前语言 → en → zh → th` 的顺序降级，不报错、不空白。

---

## 十一、给开发或 AI 的一句话说明

```text
CityOne 多语言方案分为两部分：
1）静态 UI 文案统一放入 i18n 词典，管理端与用户端共用同一套中 / 泰 / 英语言机制，默认跟随系统 / 浏览器语言，并支持手动切换；
2）动态运营内容在后台录入时只需填写一种语言，系统自动通过 AI 翻译补齐另外两种，并统一保存为 { zh, th, en } 结构。前端展示时通过统一多语言读取函数按当前语言取值，并按 当前语言 → en → zh → th 的顺序降级兜底。

最终目标不是人工维护三套内容，而是实现系统级三语自动化承接。
```
