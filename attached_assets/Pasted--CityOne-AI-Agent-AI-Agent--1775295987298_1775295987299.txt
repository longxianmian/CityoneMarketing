# CityOne AI Agent 会话记忆改造文档（后端）

## 一、改造目标

解决当前问题：

* 用户从 AI Agent 点击按钮跳转到福利中心或其他页面后，再返回聊天页，历史消息被清空。
* 同一用户每次进入 Agent 都像新会话，无法形成“助理连续性”。

后端本次改造目标：

1. 给每个用户提供可复用的 Agent 会话。
2. 把聊天消息持久化保存，而不是只返回给前端。
3. 支持前端返回聊天页时恢复最近活跃会话。
4. 为后续长期记忆、偏好记忆打基础，但本次先不做复杂长期记忆。

---

## 二、改造原则

1. 不推翻现有 Agent 架构，只补“会话层 + 消息层”。
2. 先做最小闭环：同一用户返回后能恢复最近会话。
3. 当前项目既然后端主要是 JSON 文件持久化，P0 继续沿用 JSON 即可。
4. 不做无限记忆，只保留最近活跃会话与消息。

---

## 三、建议新增的数据文件

在 `data/` 下新增：

```text
data/
├─ agent-sessions.json
└─ agent-messages.json
```

### 1）agent-sessions.json

用于保存会话主记录。

建议字段：

```json
[
  {
    "session_id": "as_xxx",
    "line_user_id": "u_xxx",
    "user_id": "user_xxx",
    "status": "active",
    "scene": "agent_main",
    "created_at": "2026-04-04T10:00:00.000Z",
    "last_active_at": "2026-04-04T10:05:00.000Z"
  }
]
```

### 2）agent-messages.json

用于保存消息记录。

建议字段：

```json
[
  {
    "message_id": "am_xxx",
    "session_id": "as_xxx",
    "role": "user",
    "type": "text",
    "text": "帮我看看积分怎么兑换",
    "payload": null,
    "created_at": "2026-04-04T10:01:00.000Z"
  },
  {
    "message_id": "am_xxx2",
    "session_id": "as_xxx",
    "role": "ai",
    "type": "tool_card",
    "text": "你可以进入积分兑换中心查看可兑换商品。",
    "payload": {
      "card_type": "link",
      "title": "积分兑换中心",
      "action": "/welfare?tab=points"
    },
    "created_at": "2026-04-04T10:01:01.000Z"
  }
]
```

## 四、建议新增的后端服务

建议新增：

```text
src/services/agent-session-service.js
```

职责：

1. 根据 `line_user_id` 查最近活跃会话。
2. 若无会话，则创建新会话。
3. 读取某个会话的消息列表。
4. 写入用户消息。
5. 写入 AI 消息。
6. 更新 `last_active_at`。

### 必备方法建议

* `getLatestActiveSession(lineUserId)`
* `createSession({ lineUserId, userId, scene })`
* `getOrCreateSession({ lineUserId, userId, scene })`
* `listMessages(sessionId)`
* `appendMessage(sessionId, message)`
* `touchSession(sessionId)`

## 五、建议新增/补充接口

### 1）初始化会话

#### `POST /api/agent/session/init`

作用：

* 根据 `line_user_id` 查最近活跃会话
* 有就直接返回该会话
* 没有就创建新会话
* 同时返回最近消息

返回建议：

```json
{
  "code": 200,
  "data": {
    "session_id": "as_xxx",
    "restored": true,
    "messages": []
  }
}
```

### 2）获取会话消息

#### `GET /api/agent/session/:sessionId/messages`

作用：

* 返回该会话历史消息
* 建议默认返回最近 50 条

### 3）发送消息

#### `POST /api/agent/session/:sessionId/message`

改造要求：

* 用户消息先入库
* Agent 回复生成后也入库
* 最后把 AI 回复返回前端

### 4）获取最近活跃会话（可选但建议加）

#### `GET /api/agent/session/latest?line_user_id=xxx`

作用：

* 让前端即使没有本地 session_id，也能恢复最近会话

## 六、现有消息发送逻辑改造要求

当前发送消息接口不能只做：

* 收到文本
* 算出回复
* 直接返回

必须改成：

1. 校验 session 是否存在
2. 保存 user message
3. 执行意图识别 / 工具调用
4. 生成 AI 回复
5. 保存 ai message
6. 更新 session 最近活跃时间
7. 返回结构化回复

这一步是本次改造核心。

---

## 七、会话复用规则建议

### P0 规则

同一 `line_user_id` 默认只保留一个最近活跃主会话：

* `scene = agent_main`
* `status = active`

用户再次进入 Agent 时：

* 优先恢复最近活跃主会话
* 不要默认新建会话

### 会话失效规则建议

可先简单处理：

* 最近 7 天内有活动的会话可恢复
* 超过 7 天可仍恢复，或者后续再加归档逻辑

P0 不必复杂。

---

## 八、消息上限建议

避免消息无限增长，建议：

* 单会话默认只返回最近 50 条消息给前端
* 文件里可保留更多，但接口先截断
* 后续再做摘要或长期记忆

本次先不做复杂摘要。

---

## 九、日志与兼容要求

### 1）兼容现有结构化消息

保存消息时，不能只存 text，要同时存：

* `type`
* `payload`

否则前端恢复历史消息后无法正确渲染卡片。

### 2）按钮消息要可恢复

例如“积分兑换中心”这种卡片按钮，恢复后必须还能显示。

### 3）后续长期记忆先不做

这次只做会话恢复，不做偏好画像、不做复杂长期总结。

## 十一、验收标准

满足以下即通过：

1. 用户进入 Agent，创建或恢复会话。
2. 用户连续发送 3 条消息，AI 回复 3 条，消息已写入后端。
3. 用户点击“积分兑换中心”跳到福利中心。
4. 用户返回 Agent 后，仍能看到之前消息。
5. 用户继续发送“刚才那个怎么兑换”，Agent 可在同一会话继续回复。

---

## 十二、给 replitAI 的一句话要求

**本次后端改造重点不是重做 AI，而是给现有 Agent 增加“会话持久化 + 最近活跃会话恢复”能力，确保用户跳转页面后返回仍能继续原对话。**
